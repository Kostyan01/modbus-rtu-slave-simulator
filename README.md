# Modbus RTU Slave Simulator

Самостоятельный Windows WPF-симулятор до 10 независимых Modbus RTU COM-портов. На каждом порту настраивается собственная линия с устройствами, параметрами связи и журналом обмена. Проект повторяет общий рабочий сценарий конфигурирования и наблюдения за устройствами, но не копирует код, оформление или бренд MasterOPC.

## Возможности

- До 10 портов с отдельными COM, baud rate, parity, stop bits (8 data bits, без аппаратного flow control) и допустимой паузой между частями кадра (5–200 мс, по умолчанию 30 мс); порты запускаются и останавливаются вместе, отдельные порты можно отключать флажком.
- До 247 slave ID на каждой RTU-линии; одинаковые имена устройств и ID допустимы на разных портах.
- Новое устройство создаётся с пустыми картами всех четырёх областей; адреса добавляются вручную.
- Копирование выбранного устройства создаёт независимую копию всех областей, тегов и текущих значений с новым свободным ID.
- Раздельные карты Coils, Discrete Inputs, Holding Registers и Input Registers.
- Имя каждого тега редактируется в карте памяти; имя уникально в пределах устройства.
- Holding/Input-регистры показываются деревом: 16 именуемых битов синхронизированы со словом, а Float32 занимает два последовательных регистра с выбором порядка байтов/слов.
- Редактирование адресов и значений во время работы без пересоздания тегов; новые адреса добавляются через вкладку карты.
- Немодальное окно сценариев: можно переключаться на вкладки основной программы, не закрывая редактор. Редактор кода и дерево тегов/виртуальных переменных находятся рядом; дерево раскрывается по мере просмотра. Щелчок по тегу, виртуальной переменной или именованному биту вставляет ссылку в код: для устройства-владельца — `THIS.Tag`, для остальных устройств — полный адрес.
- Сценарий выбирает один из трёх режимов: разовый (запускается кнопкой), циклический (интервал 50–60000 мс) или событийный.
- Во вкладке устройства «Виртуальные переменные → Выполнить макрос» можно связать переменную с любым общим или внутренним сценарием в событийном режиме. BOOL запускает макрос, пока значение TRUE; для числовых типов задаются >, <, <=, >= или = порогу; TIME не поддерживает вызов макроса. Истинное условие проверяется примерно каждые 50 мс и вызывает макрос на каждом цикле, пока остаётся истинным.
- Общие сценарии видят устройства всех включённых портов и адресуют их как `ПсевдонимПорта.Устройство.Тег` (например, `LineA.BRMOD1.Command`); псевдоним стабилен при смене COM-порта. Имена с пробелами заключаются в кавычки.
- У каждого устройства могут быть собственные внутренние сценарии с теми же режимами запуска; они хранятся вместе с устройством и копируются при его дублировании. Вызовы внутренних сценариев также сохраняются при копировании и перенаправляются на копию. В них `THIS.Tag` всегда обозначает устройство-владелец.
- У каждого устройства есть список виртуальных переменных с типом ST. Значения общие для его сценариев и сохраняются в конфигурации; обращаться к ним можно как к тегам: `THIS.Ready` или `Порт.Устройство.Ready`.
- Сценарии на распространённом ядре IEC 61131-3 Structured Text (ST): типизированные `VAR`, присваивания `:=`, условия `IF/ELSIF/ELSE`, `CASE`, циклы `FOR`, `WHILE`, `REPEAT`, арифметика, сравнения и логические операторы.
- Привязка переменных к тегам явная: `temperature := Device1.Temperature;`, обратная запись: `Device1.Temperature := temperature;`. Именованный бит регистра читается и записывается как `Device1.Status.Alarm`; имена устройства/тега с пробелами можно заключать в кавычки.
- Преобразования включают `NORM_X`, `SCALE_X`, `LIN_SCALE`, `LIMIT`, `MIN`, `MAX`, `ABS`, `SQRT`, `ROUND`, `TRUNC` и типовые преобразования `BOOL`, `BYTE`, `WORD`, `UINT`, `INT`, `DINT`, `REAL`, `LREAL` и другие поддерживаемые типы.
- Переменные блоков `TON`, `TOF`, `TP` сохраняют состояние между циклами сценария; время задаётся литералами `T#250ms`, `T#2s`, `T#1m30s`. Для работы таймеров выберите циклический запуск.
- Во вкладке редактора сценариев есть справка с примерами ST, преобразований, битов и таймеров. Поддерживается ST-ядро, но не полный стандарт IEC: массивы, структуры, пользовательские функции/функциональные блоки и строковые переменные пока не реализованы. Скрипты старого собственного синтаксиса нужно переписать на ST.
- JSON импорт/экспорт конфигурации, имён тегов и сценариев.
- Открытие конфигурации: `Ctrl+O`; сохранение: `Ctrl+S` (для новой конфигурации сначала откроется диалог выбора файла). Для другого имени/пути используйте «Сохранить как».
- Раздельные журналы обмена и предупреждений, до 5000 записей в каждом; автопрокрутку можно отключить для просмотра истории, а кнопка очищает оба списка. По команде записывается CSV-журнал событий за указанный интервал от 1 секунды до 24 часов в папку открытой/сохранённой конфигурации.
- Журнал обмена и предупреждений отображается для выбранного порта; при выборе устройства остаётся журнал его линии. Общие сообщения программы доступны отдельно.
- Поддержка функций 01, 02, 03, 04, 05, 06, 0F и 10; необслуживаемые адреса возвращают exception 02.

Адреса в карте и запросах нумеруются с нуля и редактируются прямо в строке регистра. Для запросов Modbus с известной длиной кадр собирается по ожидаемому размеру и проверке CRC, поэтому ответ не задерживается на полный настроенный интервал; этот интервал применяется только к незавершённым кадрам и помогает пережить разбиение данных драйвером. Для Float32 значение и порядок байтов/слов редактируются там же; второй регистр пары скрыт из списка и автоматически пересчитывается.
Coils и Discrete Inputs принимают значения 0 или 1; остальные области используют 16-битные значения.
Для сценариев именованные биты регистров читаются как 0/1 и принимают только 0 или 1 при записи; их можно вставлять из дерева тегов в ST-код. Старые режимы запуска по чтению/записи, регистровым сравнениям и битовым фронтам при импорте переводятся в разовый режим; для событийного запуска настройте правило в таблице виртуальных переменных. Чтение и запись тега Float32 в ST используют всю пару регистров и сохраняют точность значения, в том числе при промежуточной переменной `REAL`. Float32 кодируется в IEEE-754 и занимает два последовательных Holding/Input-регистра; чтение доступно через FC03/FC04, запись Holding-регистров — через FC16. Порядок ABCD, CDAB, BADC или DCBA настраивается для каждой пары. Области Holding и Input остаются раздельными.
Мастер, запрашивающий два слова для 32-битного `UInt`, требует явного наличия обоих адресов в карте (например, 10000 и 10001); незаполненные адреса возвращают exception 02.

Пример ST-сценария:

```iecst
VAR
    counter : UINT;
    alarm : BOOL;
    delay : TON;
END_VAR

counter := Device1.Counter;
counter := counter + 1;
delay(IN := counter >= 100, PT := T#2s);

IF delay.Q THEN
    alarm := TRUE;
END_IF;

Device1.Counter := counter;
Device1.Status.Alarm := alarm;
```

Сценарии выполняются на потоке интерфейса, ограничены 100000 операциями и не имеют доступа к файловой системе, процессам или произвольному .NET-коду. Циклический интервал и проверка событий используют таймер интерфейса; длительный сценарий может задержать следующий запуск и обработку Modbus-кадра.

## Сборка и запуск

Требуется Windows и .NET 8 SDK. Откройте `ModbusRtuSimulator.csproj` в Visual Studio 2022 или выполните:

```powershell
dotnet restore
dotnet build
dotnet test Tests/ModbusRtuSimulator.Tests/ModbusRtuSimulator.Tests.csproj
dotnet run
```

## Создание установщика Windows

Готовый x64-установщик включает приложение и .NET 8 Runtime, поэтому на целевом компьютере не нужно отдельно устанавливать .NET. Поддерживаются 64-разрядные Windows 10 и Windows 11.

Для создания установщика требуются .NET 8 SDK и Inno Setup 6. Из корня проекта выполните:

```powershell
dotnet publish .\ModbusRtuSimulator.csproj --configuration Release --runtime win-x64 --self-contained true --output .\Installer\publish
$compiler = @("${env:ProgramFiles(x86)}\Inno Setup 6\ISCC.exe", "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe") | Where-Object { Test-Path -LiteralPath $_ } | Select-Object -First 1
if (-not $compiler) { throw "Установите Inno Setup 6." }
Push-Location .\Installer
try {
    & $compiler .\ModbusRtuSimulator.iss
    if ($LASTEXITCODE -ne 0) { throw "Сборка Inno Setup завершилась с ошибкой." }
} finally {
    Pop-Location
}
```

Файл `Installer\Output\ModbusRtuSimulator-Setup-1.0.0-x64.exe` — готовый установщик. По умолчанию программа устанавливается для текущего пользователя в `%LOCALAPPDATA%\Programs\Modbus RTU Simulator`; права администратора не нужны. Установщик добавляет ярлык в меню «Пуск», а ярлык на рабочем столе можно включить во время установки. Краткая инструкция для пользователей находится в `Installer\README.txt`.

Готовый установщик можно скачать на странице [последнего релиза](https://github.com/Kostyan01/modbus-rtu-slave-simulator/releases/latest).

Старые одно-портовые JSON-конфигурации автоматически открываются как конфигурация с одним портом `Порт1`. Для RTU-проверки обычно нужен второй физический COM-порт или виртуальная пара COM-портов; нельзя повторно открыть COM-порт, занятый другим приложением.
